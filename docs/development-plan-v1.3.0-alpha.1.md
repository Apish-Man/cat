# CatMate v1.3.0-alpha.1 开发计划

**首个里程碑定在第 3 个开发日**：在 M4 桌面运行导出的 arm64 应用，点猫有反馈，点透明处能操作后方应用，拖出原窗口后松手能继续工作。通过这次演示，再投入正式猫模型和动画。

按一名开发者全职投入估算，基础工作量为 **15 个开发日**，另留 **3 天机动**。D1 指实际开工日。估算假设能取得有分发授权、可适配的基础猫模型；完整的原创建模、绑定和动作制作需要单独估时。工作分解保留原始排期。开发机已完成简模和橘猫的桌面输入验证，实际验收进展见[开发机验证记录](validation/macos-v1.3.0-alpha.1.md)。[实现方案](implementation-v1.3.0-alpha.1.md) · [预览版范围](releases/v1.3.0-alpha.1.md)

## 工作分解

每项按一天安排。交付物可以直接用于演示、测试或评审。

| 开发日 | 阶段 | 当日任务 | 可检查的交付物 |
| --- | --- | --- | --- |
| D1 | P0 原型 | 核对 Godot 4 与匹配的导出模板，建立独立的 `mac/` 工程，放入能辨认朝向的简模 | 从项目根目录按记录的步骤导出 arm64 应用，可在编辑器外打开并退出 |
| D2 | P0 原型 | 接入透明置顶窗口、角色命中轮廓和拖动捕获 | 在带按钮和文本输入框的后方应用上复测，点击空白处只触发一次，拖动结束后可以继续输入 |
| D3 | P0 原型 | 加入菜单栏退出，覆盖越界松手、取消和不同显示缩放；记录空闲采样 | 完成首次真机演示，记录引擎、后端、模板、性能预算初值及需要 AppKit 补足的具体能力 |
| D4 | P1 行为 | 在 `mac/core/` 实现待机、行走、目标选取和边界计算，用可控时钟及随机种子驱动 | 同一输入可重放；30、60、120 Hz 下到达同一目标，建议终点偏差不超过 1 逻辑点 |
| D5 | P1 行为 | 接入“轻抚打断行走、拖动优先、松手重新待机”，处理失焦和长帧 | 无界面测试覆盖完整交互序列、负坐标、屏幕变化及休眠时间跳变 |
| D6 | P2 角色 | 确认一只可分发的猫，记录来源、许可、骨骼、比例、朝向与脚底锚点 | 可独立预览的角色场景、授权记录，以及缺失动作清单 |
| D7 | P2 角色 | 配置待机、行走与轻抚反馈，将动作和实际移动速度接入 AnimationTree | 可对照查看起步、停步、转向和摸头；角色到达屏幕边缘时停止踏步 |
| D8 | P2 角色 | 校准头身轮廓与缩放，把开发简模替换为正式角色 | 用相同的交互序列分别运行简模和猫模型；行为核心无需识别模型名和骨骼名 |
| D9 | P3 集成 | 串联桌面输入、行为、动画和窗口定位 | 导出的应用可完成“散步 → 摸头 → 拖动 → 松手 → 再散步”，缩放时脚底位置稳定 |
| D10 | P3 集成 | 接入菜单栏找回、缩放与省电偏好、本地原子保存 | 退出重启能恢复；显示器移除可找回；损坏偏好可恢复默认，未来格式保留原文件 |
| D11 | P3 集成 | 调整静止与隐藏时的刷新策略，在 M4 上复测睡眠唤醒 | 同机采集空桌面、待机、连续散步各十分钟的 CPU、内存和能源影响，另记唤醒频率及帧间隔 |
| D12 | P3 集成 | 回归透明区首次点击、混合缩放、输入取消、位置恢复及 Windows 原有单测 | 输出带版本与复现步骤的测试记录；影响桌面操作的问题修复后回测 |
| D13 | P4 候选包 | 用干净检出导出 Mac 候选包，核对依赖、模型授权及签名条件 | 可追溯到提交的 ZIP、构建步骤和实际签名／公证状态 |
| D14 | P4 候选包 | 在另一用户环境解压候选包，实测首次启动、找回、退出与重新启动 | 安装记录覆盖最低已验证系统，发布说明写明实测设备、资源占用和已知限制 |
| D15 | P4 预发布 | 核对待发布提交与候选包，生成 SHA-256，整理 GitHub 预发布草稿 | 草稿中的标签、ZIP、校验值和说明相互对应；包若有修改，重新执行 D14 并计算摘要 |

**依赖顺序**为 P0 验证桌面交互，P1 完成行为契约，P2 按契约适配首只猫，三者在 P3 汇合，P4 使用验证通过的提交构建。若有人协助，可从 D1 并行核查模型来源与授权；待脚底锚点和动作名确定后，角色制作可与 P1 并行。

## 检查点与延期处理

- **D3 决定原生桥接范围。** 若透明处吞点击、拖动无法释放或后方输入失去焦点，保留最小复现，优先用机动时间修桌面适配层。行为测试可继续在屏幕替身上推进。根据原型实测重新估算余下工期。
- **D8 交付可操作的猫。** 若模型授权或动作适配仍有缺口，用简模继续集成，并单列素材依赖及预计到位日。只有可分发的正式角色进入候选包。
- **D12 决定能否出候选包。** 对照 D3 的同机预算检查能耗和唤醒。出现持续空闲高负载、拖动卡死或角色无法找回时，使用机动时间修复，并重跑相关场景。
- **D15 决定能否预发布。** 依据 D14 的独立安装记录填写支持范围和分发状态。三天机动用尽仍有影响安装或桌面操作的问题，顺延预发布，更新日期及具体阻塞项。

每个工作包沿用一个短分支，合入时附上对应演示、测试输出或采样记录。下一阶段的窗口边缘行走与跳跃在此次预览验收后另立计划。

## 开工任务

从包含本计划的基线创建 `feat/mac-desktop-prototype`。第一笔实现提交交付 `mac/project.godot`、一个简模场景、macOS 导出配置和复现步骤。验收人应能按说明在 M4 上启动导出的应用并退出；D2 再用这个可运行包接入穿透与拖动。
