# CatMate v1.3.0-alpha.1 实现方案

**交付目标**是在 Apple Silicon Mac 上运行一个独立的 arm64 应用。一只内置的 3D 猫会待机、自己散步、回应轻抚，并能被拖到屏幕另一边。用猫旁边的空白处仍能操作其他应用。用户可以从菜单栏找回小猫或退出。本文是待实施的工程方案。产品范围见[预览版说明](releases/v1.3.0-alpha.1.md)，Windows v1.2.0 与目标架构的关系见[架构说明](architecture.md)。

## 1. 第一项工程决策

先在导出的应用里用简模验证**点猫有反馈、点透明处能操作后方应用、拖猫出窗口后能正常松手**这三个动作。这三项同时成立，才值得投入正式猫模型和动画。第一轮只需一个能辨认朝向的简模、一个透明小窗口和一个菜单栏退出项。

在同一仓库下新增独立 Godot 工程，原有 Python/PySide6 应用继续按 Windows 流程构建。两端共享动作的含义、测试场景和设计素材说明，各自发布。Mac 端不读取 Windows 存档。窗口顶边行走、跨窗口跳跃、用户导入模型和养成迁移属于后续迭代。

## 2. 模块与依赖

下表是拟新增的路径。使用一个应用进程，在启动场景显式装配模块。按职责拆目录即可，首版无需插件市场、进程间通信或全局事件总线。

| 路径 | 拥有的数据与职责 | 边界 |
| --- | --- | --- |
| `mac/project.godot`、`mac/app/` | 创建窗口、组合对象、调度事件和时钟、控制退出顺序 | 唯一同时认识平台、行为、表现和存储的地方 |
| `mac/core/` | 行为状态、脚底位置、行走目标、移动速度。实现确定性步进和边界计算 | 接受逻辑点、时间差和语义输入。不读取指针、文件、骨骼或系统窗口 |
| `mac/desktop/` | 桌面适配接口、Godot 窗口实现与测试替身。统一屏幕几何、输入、命中和菜单事件 | 每次位移只有一个窗口写入者。引擎已支持的能力优先用公开 API |
| `native/macos/` | 按需实现 Godot 适配层缺少的 AppKit 能力。通过 GDExtension 暴露给桌面适配器 | Objective-C++ 及窗口句柄止于此。在主线程操作窗口、注销观察者 |
| `mac/presentation/`、`mac/characters/cat/` | 正交相机、角色场景、AnimationTree、脚底锚点、动作映射和命中轮廓 | 消费动作和实际移动速度。角色动画仅在本地坐标内播放 |
| `mac/settings/`、`mac/tests/` | 前者负责版本化偏好、校验与恢复。后者容纳纯逻辑测试、替身和交互测试场景 | 测试使用隔离目录。角色资源验证可单独执行 |

AppKit 桥接按具体差距引入。先在同一小窗验证 Godot 原生窗口的透明合成、置顶和 `mouse_passthrough_polygon`，以及菜单和显示器变化通知。对不满足验收的能力，记录复现条件，再由同一个桌面接口切换实现。锁定引擎、导出模板、渲染后端和必要的 godot-cpp 版本后，在全新目录复现 arm64 导出。[Godot 窗口与命中区域](https://docs.godotengine.org/en/stable/classes/class_window.html#class-window-property-mouse-passthrough-polygon) · [GDExtension](https://docs.godotengine.org/en/stable/tutorials/scripting/gdextension/what_is_gdextension.html)

## 3. 接口与行为

以下是工程内部约定，方法名可调整，单位、所有者和失败语义应随测试固定。

| 调用方向 | 交换的数据 | 可测试的约定 |
| --- | --- | --- |
| 桌面 → 应用 | 屏幕快照含修订号、显示器标识、可用矩形、缩放。输入含类型、桌面位置和单调时间 | 桌面采用主屏左上为原点的逻辑点，保留负坐标。适配器转换 AppKit 原点和 Retina 比例。像素仅在渲染及设置命中区域时使用 |
| 应用 → 核心 | `step(dt, events, screens)`。测试可注入随机种子 | 返回新脚底位置、朝向、实际速度和动作。相同初值、时钟、种子与输入产生同一轨迹 |
| 应用 → 桌面、角色 | 用脚底位置定位窗口。用动作和速度驱动动画 | 窗口原点等于目标脚底减去局部脚底偏移。缩放时保留脚底。步态由实际位移驱动，到边界时不会原地踏步 |
| 角色 → 桌面 | 将头部与身体的交互轮廓投影到窗口局部坐标 | 按姿态、朝向、缩放变化更新。以真实后方窗口验证空白处的首次点击。拖动期间保留输入捕获，松手或取消后恢复普通命中 |
| 应用 ↔ 偏好 | `schema_version`、显示器标识、可用区域内相对位置、缩放、省电开关 | 首启使用默认值。拖动结束、设置变更和正常退出写盘，临时文件写完后原子替换。坏档备份后恢复默认。遇到未来格式维持会话默认值并保留原档 |

**从散步切换到拖动。** 假设猫正在向右走。按下猫身时记录指针到脚底的偏移并暂停旧目标。移动超过阈值后进入拖动，按偏移更新位置。松手后将猫身夹回当前屏幕可用范围，清掉旧目标，从新位置重新待机。短按头部或光标划过头部可触发轻抚反馈，设冷却避免逐帧重复触发。拖动判定优先于短按。丢失焦点、输入取消和显示器断开都要释放捕获。

**状态与时钟。** 自主状态只有待机与行走。轻抚是有结束信号和超时兜底的短动作，拖动是受用户控制的状态。拖动优先于轻抚，轻抚优先于自主选择。行走的目标从当前可达区域采样，按经过的秒数加减速。睡眠或长帧后丢弃积压时间，再按当前几何定位。静止时降低动画与决策频率，系统事件仍可立即唤起交互。

**找回与恢复。** 按显示器标识和相对位置恢复。原屏消失时使用当前可用屏幕并夹回可见区域。菜单栏“找回小猫”取消拖动、移动至可见位置并保存。收到退出事件后先结束输入捕获和定时器，再保存偏好、释放菜单与系统回调。测试重复找回、重复退出事件以及一次拖动中的屏幕变化。

几何测试应包含一个偏离主屏原点的例子。设主屏高 900 点，左侧副屏上一点的 AppKit 全局坐标为 `(-120, 650)`，转换后的桌面位置应为 `(-120, 250)`。副屏的 Retina 倍率只参与该窗口内的渲染换算。切屏时先应用新的几何快照，再重新投影脚底与命中区域。旧快照产生的待执行定位命令应丢弃。

## 4. 扩展点的使用示例

- **第二只角色**提供一个角色资源，包含模型场景、朝向、比例、脚底锚点、头身轮廓及逻辑动作映射。入库时检查待机、行走及轻抚反馈。可选动作缺失时回落到待机。用同一套交互和移动测试更换两种体型的测试模型，验证核心不依赖骨骼命名。
- **窗口边缘**在下一阶段给桌面适配器添加可选的支撑面快照，记录标识、端点和修订号。核心只用可行走线段及脚底相对位置。窗口消失时使支撑失效并回落到屏幕区域。首版仅实现屏幕边界，基础散步无需读取其他应用窗口或申请全局输入权限。
- **新平台**可实现相同的屏幕、命中和窗口定位接口。在接入原生实现前先用测试替身跑轨迹和交互用例。若只增加一段猫咪动画，变更应集中在角色资源和动作选择，平台代码无需随之发布接口变更。

## 5. 实施顺序与交付物

| 工作包 | 依赖 | 完成条件及失败时的处理 |
| --- | --- | --- |
| P0 桌面原型 | 无 | 导出 arm64 简模应用，在普通应用前验证透明、置顶、点击穿透、越界拖放和菜单退出，记录当前应用焦点。透明处吞点击或拖动无法释放时，在桌面适配层修复，复测后确定后端及原生桥接范围 |
| P1 行为与移动 | 接口确定后可与 P0 并行 | 用屏幕替身和固定种子重放待机→走→拖→松手。覆盖长帧、负坐标和缩放。交付 headless 测试入口以及一份可重放的输入序列 |
| P2 首只猫 | 角色契约确定后可与 P0/P1 并行 | 模型、动作、命中轮廓和来源清单入库。完成待机、行走、抚摸反馈，拖动姿态可复用。简模可用于开发，发布附件须使用具备分发权且通过动作验证的猫模型 |
| P3 集成与常驻 | P0、P1、P2 | 接通原生输入、动画和配置。验证跨缩放命中、菜单找回、坏档恢复、退出重启、M4 睡眠唤醒以及空闲降帧。保留复现步骤和采样数据 |
| P4 导出与预发布 | P3 | 从干净检出构建，核验 arm64、模型与依赖许可、签名及公证实际状态。在另一用户环境运行最终压缩包解压后的应用。通过后更新版本说明、生成 SHA-256、以预发布方式上传 |

建议将 P0、P1、P2、P3、P4 各自作为可独立评审的改动。第一笔实现提交只包含导出原型和操作记录。P0 结论决定后续原生适配成本。每笔改动附对应证据，标签指向最终通过验证的提交。

单人开发时按 P0 → P1 → P2 → P3 → P4 推进。多人开发时，平台开发负责 P0，行为开发负责 P1，角色制作负责 P2。三路用同一脚底锚点、动作名和桌面坐标约定在 P3 汇合。P0 的交接物包含可运行的简模应用、复现操作，以及引擎后端、最低系统候选、常驻指标预算的决策记录。最低系统版本以 P4 实际跑过的环境为准。

## 6. 验收与发布

| 层级 | 验证场景 | 证据和放行条件 |
| --- | --- | --- |
| 纯逻辑 | 30/60/120 Hz 到达同一目标。小步长误差。停顿恢复。目标被拖动抢占。非法偏好值和旧屏幕缺失 | 固定种子与输入记录可重放。终点误差预算建议为 1 逻辑点。恢复后无跳跃，位置有效。可移植[已有运动用例](../tests/test_motion.py)的场景 |
| 真机输入 | 猫身、头部、透明区、缩放前后、拖出窗再松手。后方应用处于文字编辑状态 | 导出应用前后各做一次。后方按钮只触发一次，编辑焦点可继续使用，松手后后方应用能再次接收输入 |
| 常驻与性能 | 同台 M4、相同显示设置和电源条件，记录空桌面、待机及散步各十分钟。另测隐藏、省电及睡眠恢复 | 记录 CPU、内存、帧间隔、能源影响和采样方式。空闲时唤醒应少于持续走动，隐藏时暂停不必要绘制。若趋势相反或恢复异常，保留诊断采样并修复后复测。绝对预算由 P0 实测确定 |
| 安装与回归 | 干净工作区构建、另一用户解压启动。启动后找回与退出。独立偏好目录。原有 Windows 测试仍通过 | 记录提交、引擎和模板版本、系统与设备、分发状态、包校验值及已知限制。以最终附件验证启动，避免只在编辑器内验收 |

Mac 产物建议为 `CatMate-v1.3.0-alpha.1-macos-arm64.zip` 和同名 `.sha256`。预览版号写在 Mac 导出配置中。按实际分发条件选择签名路径并在安装说明标明结果，使用 Developer ID 公证时还要核验公证票据。原有[发布流程](releasing.md)中的 Windows 打包命令用于 Windows 系列。Mac 验收记录与附件准备齐全后，为对应提交创建预发布标签，GitHub Release 标记为 **Pre-release**。[Godot macOS 导出](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_macos.html)
