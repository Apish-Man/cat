# 1.1 流畅度与性能验证

最终正式 EXE 在仅显示桌宠、未展开小屋的 8.025 秒样本中：工作集 **77.77 MiB**、私有内存 **45.07 MiB**，进程响应正常，日志为空。此样本 CPU 时间增量低于采样分辨率，不代表零消耗。原始记录：`performance-packaged-final.json`。完成测量后还逐项对照了更新前后存档：名字、积分、库存、已穿服装和工作历史均保留。

最后一轮优化将小屋改为首次打开时创建；仅靠小猫右键启动、调大小、省电和定位不会创建小屋。下面的源代码隔离场景数据在这一轮优化前取得，包含已构造但隐藏的小屋；因此不能把它当作最终 EXE 每个场景的固定内存。穿衣补测见 `performance-native-costumes.json`：穿衣走动约 103.71 MiB / 5.725% 单逻辑核 CPU，穿衣逗猫棒扑跳约 112.63 MiB / 12.758% 单逻辑核 CPU，折算 16 核口径的整机约 0.36% / 0.80%。

环境：Windows 10 x64 19045、16 逻辑处理器、PySide6 Essentials 6.12.0、240 像素猫咪。使用独立临时存档，真实 Windows Qt 窗口和事件循环。优化前每场景 5 秒，最终版每场景 6 秒，启动/切场景后先等待 300 ms。CPU 为进程 CPU 时间 / 实际秒数，100% 表示占满一个逻辑处理器；整机比例再除以 16。

提高帧率和插值会增加活动时的绘制工作；本次没有把活动 CPU 增加描述成降低。默认走动与激光互动分别折算为整机约 0.33% 和 0.62%。省电模式走动 CPU 比默认约低 55%。睡觉期间 CPU 低于本次短窗口采样的有效分辨率；0% 不表示完全没有 CPU 消耗。打开小屋后 Qt 字体/控件缓存可能继续保留，所以省电后段工作集不能直接与“从未展开小屋”的初段比较。

数据为本机短时测量，会随屏幕 DPI、猫咪大小、衣服、系统负载和 Qt/显卡后端变化，不能当成其他电脑或长时间运行的固定上限。缓存上限及反复改大小/衣服的检查用于防止持续增长。

原始数据：`performance-native-before.json`、`performance-native-final.json`。中间版本数据保留在 `performance-native-after.json`；离屏数据只作开发参考。
