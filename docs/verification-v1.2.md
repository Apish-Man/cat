# 1.2 走路重影修复

原因：1.1 把不同腿位的两张照片按透明度叠化，重叠区虽然接近不透明，两个不同轮廓仍会同时出现。只检查不透明度不能证明没有重影。

修复：

- 裸猫和六套服装各自离线生成 24 个单来源形变步态帧，共 168 帧；每个中间帧只采样一张经过位移校正的照片，不做两张照片的颜色/透明度叠加。
- 运行时每个走路相位选择一个完整帧。走路的起步、停靠、转向和换装不叠加旧轮廓。
- 每次绘制先清空透明背景，避免保留前一帧像素。
- 取消额外的整身 1 像素跳动。按 60/30 Hz 的绝对截止时间调度，减少固定 16 ms（62.5 Hz）和屏幕 60 Hz 不匹配的节拍差；忙时跳过迟到帧，不高速补画。

资源：图像形变使用的 OpenCV、NumPy、Pillow 仅用于开发时生成 PNG，打包时显式排除，运行时不做光流计算。只加载当前一套步态图，绘图缓存仍限制为 8 MiB。开发重建依赖在 `requirements-assets.txt`，脚本为 `tools/bake_walk.py`。

验证：

- 25 项业务/运动/节拍单元测试通过。
- 原有界面、玩具、服装和存档集成检查通过。
- `tools/verify_walk.py` 对每个步态相位及起步/停靠/转向进行检查：禁止调用图片叠化函数；确认七套步态各有 24 帧；确认桌宠进程不导入 OpenCV/NumPy。
- Windows 实测 4 秒绘制 240 帧，间隔中位数 16.499 ms，95 分位 18.815 ms，最大 20.715 ms；工作集 78.95 MiB。该项为 Qt 绘制事件间隔，不能等同于对所有显示器实际呈现的保证。
- 裸猫和蓝色服装中间帧的实图检查见 `previews/walk-clear-phases.png`，新的移动/扑跳预览为 `previews/motion-v1.2.gif`。

原始测量：`performance-walk-v1.2.json`、`performance-walk-pacing-v1.2.json`；离线步态元信息与校验值：`../assets/walk/manifest.json`。
